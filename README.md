# Меню недели

Планировщик рациона на неделю: база блюд, гарниры, умный генератор меню и автоматический список покупок.
Полностью клиентское приложение — все данные хранятся в IndexedDB браузера.

**Стек:** React 18 · TypeScript · Vite · Tailwind CSS · Framer Motion · Zustand · idb · React Router (HashRouter)

```bash
npm install
npm run dev      # http://localhost:5173 (без service worker)
npm run build    # статическая сборка в dist/ — можно выложить на любой хостинг
npm run host     # сборка + HTTPS-сервер в Wi-Fi сети (см. ниже)
```

## Офлайн (PWA)

Приложение — SPA с hash-роутингом, все данные в IndexedDB. Service worker (vite-plugin-pwa / Workbox)
предкэширует всё приложение, включая шрифты (они встроены в сборку, без Google Fonts), поэтому после
первого открытия оно работает без интернета и устанавливается на экран «Домой».

- Новая версия скачивается в фоне; плашка «Доступна новая версия» предлагает обновиться — данные не теряются.
- Приложение запрашивает «постоянное хранилище», чтобы браузер не удалял IndexedDB при нехватке места.
- В шапке — индикатор «Офлайн» и кнопка «Установить» (где браузер её поддерживает).
- Иконки генерируются из `public/icon.svg`: `npm run icons`.

## Хостинг по Wi-Fi через HTTPS

```bash
npm run host                          # сборка + запуск
npm run serve:https                   # запуск уже собранного dist/
npm run serve:https -- --port 9443 --http-port 9080 --trust --no-qr
```

Скрипт `scripts/serve-https.mjs` раздаёт `dist/` по HTTPS на всех адресах компьютера
(`https://192.168.x.x:8443`) и печатает QR-код для телефона.

Service worker работает только на странице с доверенным сертификатом, поэтому скрипт не ограничивается
самоподписанным сертификатом: при первом запуске он создаёт **локальный центр сертификации**
(`.cert/ca.crt`, 10 лет), а при каждом запуске выпускает серверный сертификат для текущих IP-адресов.
Установите `ca.crt` на устройство **один раз**:

1. Откройте на телефоне `http://<IP>:8080/` (QR-код в терминале) — там кнопка скачивания сертификата
   и пошаговая инструкция для iOS, Android, Windows и macOS.
2. Откройте `https://<IP>:8443/` — без предупреждений, с офлайн-режимом и установкой на экран «Домой».

`--trust` добавляет сертификат в доверенные на самом компьютере (Windows — хранилище текущего пользователя,
macOS — связка ключей). Папка `.cert/` содержит закрытые ключи и не должна попадать в git (уже в `.gitignore`).
Если Windows спросит про брандмауэр — разрешите доступ в частных сетях.

## Деплой на GitHub Pages

`.github/workflows/deploy.yml` собирает приложение (`npm ci` → `npm run build`) и публикует `dist/`
при каждом пуше в `main` (или вручную: Actions → Deploy to GitHub Pages → Run workflow).

Один раз в репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
Адрес — `https://<пользователь>.github.io/<репозиторий>/`. Пути в сборке относительные (`base: './'`),
роутинг на `#`, поэтому подпуть репозитория и обновление страницы работают без доп. настроек.
Данные пользователей лежат в IndexedDB браузера и привязаны к адресу сайта: при смене адреса
(другой репозиторий, свой домен) их нужно перенести через «Настройки» → «Данные» → экспорт/импорт.

## Архитектура (Feature-Sliced Design)

```
src/
├── app/            # инициализация, сид демо-данных, роутинг, глобальные стили
├── pages/          # menu, dishes, pantry, shopping, settings, settings-limits, settings-sides, settings-data,
│                   # settings-calories
├── widgets/        # app-header, weekly-board, dish-catalog, pantry-board,
│                   # shopping-list, settings-board
├── features/       # generate-menu, edit-meal-slot, toggle-slot-lock, skip-meal, configure-meals, configure-calories,
│                   # adjust-dish-limits, manage-pantry, clear-menu, manage-dish, manage-side-dish, shopping-list
├── entities/       # ingredient, dish, side-dish, menu, pantry (типы, сторы, репозитории, UI)
└── shared/         # api (обёртка IndexedDB), ui-kit, lib, config
```

Слои импортируют только нижележащие слои через публичный `index.ts`. Связи между сущностями
оформлены через `@x`-нотацию (`entities/ingredient/@x/dish.ts`).

## Приёмы пищи

- Завтрак, обед, ужин и салат (отдельный приём пищи). Какие из них планировать — в «Настройках».
- У каждого блюда есть категория — «Завтрак», «Основное» (обед и ужин) или «Салат», можно выбрать несколько.
- Любой приём пищи можно **исключить** (ем вне дома): он не заполняется генератором и не попадает в список покупок.
- Блюдо можно **заменить вручную** (клик по карточке или меню «⋯»: подходящие по правилам варианты идут первыми),
  **случайно** (🔀) или сменить только гарнир.

## Свои покупки

В списке покупок есть поле «Добавить в список» — для того, чего нет в меню (хлеб, фрукты, хозтовары…),
с количеством или без и быстрыми кнопками для частых покупок. Такие позиции помечены «добавлено вручную»,
стоят в своих категориях (есть новая — «Хозтовары»), запасы из них не вычитаются. Они сохраняются,
попадают в «Скопировать» и экспорт; кнопка «Убрать купленное» удаляет отмеченные.

## Заметки и рецепты

У каждого блюда есть поле «Заметки и рецепт»: советы по готовке и ссылки. Ссылки кликабельны в карточке блюда,
а в меню у блюда со ссылкой появляется кнопка 📖 «Открыть рецепт».

## Данные

«Настройки» → «Данные» (отдельная страница `#/settings/data`):
- **Скачать файл** — экспорт всех данных (блюда, гарниры, запасы, меню, служебные флаги) в один JSON
  `menu-nedeli-ГГГГ-ММ-ДД.json`; работает офлайн.
- **Импорт из файла** — загрузка ранее скачанного файла с предпросмотром содержимого и двумя режимами:
  - *Объединить* (по умолчанию): новые блюда, гарниры и запасы добавляются, для совпадающих побеждает более
    свежая версия (`updatedAt`), текущее меню остаётся, свои покупки из файла дописываются в список; повторный
    импорт того же файла ничего не дублирует;
  - *Заменить всё*: восстановление из копии — данные устройства заменяются файлом в одной транзакции
    (с предложением сначала скачать копию текущих данных).
  Файл проверяется: чужие файлы, повреждённый JSON и файлы более новой версии отклоняются с понятной ошибкой,
  неполные записи пропускаются, и их число показывается до импорта.
- **Очистить всё** — удаляет все данные на устройстве. Требует ввести слово «удалить» и предлагает сначала скачать копию.
  Демо-данные после очистки заново не добавляются.

## Гарниры

- «Настройки» → «Гарниры» (отдельная страница `#/settings/sides`; старый адрес `#/sides` ведёт туда же):
  добавление, редактирование, удаление, ингредиенты.
- Лимит «раз в неделю» и переключатель «использовать в генерации» (отключённый гарнир остаётся в базе).
- Связь с блюдами настраивается с обеих сторон: в форме гарнира («Подходит к блюдам») и в форме блюда.
  Блюдо без явного списка принимает любой гарнир.
- В строке гарнира — сколько раз он уже в меню (из лимита), к скольким блюдам привязан и какая доля ингредиентов есть дома.
- В меню гарнир меняется отдельно: «⋯» → «Сменить гарнир…».

## Запасы

Раздел «Запасы» — продукты, которые уже есть дома (с количеством или просто «есть»).
Генератор предпочитает блюда и гарниры из этих продуктов, а список покупок вычитает их:
полностью покрытые позиции уходят в блок «Есть дома», частично — показывают остаток к покупке.
Кнопка 🏠 в списке покупок переносит позицию в запасы.

## Настройки

Главная страница настроек — приёмы пищи на неделю и ссылки на подразделы.
Отдельные подразделы открываются своими страницами с «хлебными крошками» назад:
- «Лимиты блюд» (`#/settings/limits`) — сколько раз каждое блюдо может встретиться в неделю и в день;
- «Гарниры» (`#/settings/sides`) — список гарниров с лимитами, вкл./выкл., редактированием и удалением.
- «Калории» (`#/settings/calories`) — экспериментальный учёт калорий;
- «Данные» (`#/settings/data`) — экспорт, импорт и очистка всех данных.

## Калории (эксперимент)

«Настройки» → «Калории» (`#/settings/calories`) → «Учитывать калории». Пока переключатель выключен, приложение и генератор работают
как без этой функции (генератору передаётся `calories: null`), а сохранённые калории просто не показываются.

Когда включено:
- у блюд и гарниров появляется поле «Калории на порцию»; не указанные считаются как 0 ккал (с предупреждением);
- «Как считать»: *цель* — значение на день и допуск ±%, получается коридор (например 1 800–2 200 ккал),
  плохи и перебор, и недобор; *потолок* — лимит на день, важно только не превысить его, лёгкий день считается нормальным;
- строгость: *мягко* — генератор предпочитает блюда, которые укладывают день в коридор, и штрафует дни вне его,
  но заполняет все приёмы пищи; *жёстко* — блюдо или повтор, с которым день превысит максимум, не ставится
  (приём пищи может остаться пустым), выход за коридор штрафуется сильнее;
- в карточке дня показывается сумма калорий (зелёная — в коридоре, жёлтая — меньше цели, красная — больше),
  в слоте — калории порции (блюдо + гарнир), в окне выбора блюда — предупреждение, если день выйдет за норму.

Настройки хранятся в записи меню (`WeeklyMenu.calories`) и попадают в экспорт.

У демо-блюд и гарниров есть примерные калории на порцию (`entities/dish/model/demoCalories.ts`, `entities/side-dish/model/demo.ts`).
В базах, созданных раньше, они один раз дописываются демо-записям, у которых калории ещё не указаны (флаг `demo-seeded-calories`).

## Генератор меню

`features/generate-menu/lib/generateWeeklyMenu.ts` — жадный рандомизированный алгоритм с перезапусками:

- проходит активные слоты по порядку (Пн завтрак → Вс салат), закреплённые и исключённые не трогает;
- кандидаты — блюда нужной категории, у которых не исчерпан лимит «раз в неделю»;
- обеды и ужины образуют одну цепочку со строгим чередованием белка; у завтраков и салатов — свои цепочки,
  где разнообразие только предпочтительно;
- соблюдаются лимиты в неделю и в день; если блюдо можно повторить, повторы ставятся в соседние дни
  на тот же приём пищи (готовите один раз — едите 2–3 дня), с тем же гарниром;
- блюда из продуктов, которые есть в запасах, получают больший вес; запасы «расходуются» по ходу,
  чтобы одни и те же 500 г риса не засчитывались дважды;
- гарнир выбирается из разрешённых для блюда (или любой) среди включённых и не исчерпавших лимит, отличный от
  предыдущего; если гарниров не хватает, предпочтение отдаётся блюдам без гарнира;
- если правила невыполнимы, ограничение ослабляется со штрафом; из 120 попыток берётся лучшая
  (при равенстве — та, что больше использует запасы),
  а пользователь получает понятное предупреждение.
